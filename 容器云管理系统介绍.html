容器云 · 多集群运维

容器云管理系统介绍

k8man — 基于 kubeconfig 导入的轻量多集群 Kubernetes 运维管理台，统一接入、日常运维、诊断巡检与基础监控，能力边界由凭证权限决定。

产品代号 k8man
当前阶段 可用 / 持续迭代
技术栈 Go + Vue3
部署形态 单镜像 + PVC

一、项目背景

多集群运维场景下，常用 kubectl / Rancher 控制台分散操作，存在以下痛点：

🔗
集群入口分散
多套 kubeconfig、多套控制台切换频繁，缺乏统一的接入与选用视图。
🧩
权限边界不清
Cluster 管理员与 Project 凭证能力不同，难以一眼区分可操作范围。
🛠️
日常运维打断
查日志、重启 Pod、扩缩容、改 ConfigMap 常需在终端与多工具间来回切换。
📡
异常发现滞后
缺少跨集群巡检与问题摘要，节点/负载/事件异常难以及时汇聚。
目标：用一份有权限的 kubeconfig 即可接入目标集群，在同一 Web 界面完成多集群选用、工作负载运维、诊断与巡检摘要，降低日常运维切换成本。

三、技术架构

技术栈

Go 1.22 Gin client-go SQLite Vue 3 Vite Axios metrics API

架构特点

  • 前后端一体：Go 进程嵌入前端构建产物，单二进制 / 单镜像即可对外服务
  • 读写分离：/api/v1/read 只读；/api/v1/write 须 igokey 会话 Token
  • 无独立数据库：内置 SQLite（PVC 持久化），Hosts / 巡检快照一并落盘
  • 进程内巡检：每集群约 2h 一轮；有界并发默认 4、积压可扩至 8（可配）；成功开始间隔 ≥2s；同集群互斥；无需 Sidecar

资源需求（参考）

CPU1～2 核
内存512 MB～1 GB
磁盘PVC 持久化 /data（库与配置）
运行时容器镜像（Alpine + 静态 Go）
副本单副本（RWO PVC）

并发与容量

支持并发用户约 10～30 人同时在线（运维场景）
接入集群数无硬编码上限，可接入并管理 200+ 集群
数据库容量SQLite 存配置/巡检/文档，GB 级足够
后台巡检并发默认 4 路，积压自动扩至上限 8（inspect_concurrency* / K8MAN_INSPECT_*）
巡检节流与互斥成功开始间隔 ≥2s；单次超时约 45s；同集群后台与手动互斥
备份方式备份 PVC /data（含库与 Hosts）即可

四、部署可行性分析

结论：部署简单、依赖少。单镜像 + PVC 即可上线，无外部 MySQL / Redis / 对象存储依赖；适合内网或已有 Ingress 的 K8s 环境。

部署方式

☸️
Kubernetes 部署（推荐）
Deployment + Service + Ingress + PVC；滚动更新 maxUnavailable: 0，同节点亲和保证 RWO 挂载。
💻
本地单进程
go run ./cmd/server 或直接跑二进制；默认 :8080，数据目录 ./data，适合开发验证。

部署步骤（概要）

步骤 1：构建镜像
多阶段构建（Node 打前端 → Go 静态编译 → Alpine）；推送到镜像仓库
步骤 2：应用清单
kubectl apply -f deploy/k8s/k8man.yaml，创建 Namespace / Deploy / SVC / Ingress / PVC
步骤 3：滚动发布
rollout restart 后等待 Ready；健康检查 GET /api/health
步骤 4：导入集群
页面导入 kubeconfig → 测试连通与权限 → 选用后进入工作负载 / 监控 / 诊断
步骤 5：开启写操作（按需）
访问 /igokey 取钥，在 /ops 验证后获得写会话

风险与注意事项

事项 说明 建议
PVC 与滚动 RWO 卷依赖同节点挂载，跨节点可能 Pending 保持 podAffinity；观察调度
metrics-server 监控页节点/Pod 指标依赖目标集群 metrics-server 目标集群提前安装
凭证权限 Project 凭证无法 List Node，节点类诊断会跳过 按需使用 Cluster 凭证
写操作密钥 igokey 非用户体系 / SSO，适合小范围运维 控制 /igokey 可达范围
巡检并发 默认 4～8 路并行 Probe/Diagnose，会增加对目标 API Server 与本机出口的压力 按规模调整 conf / 环境变量
数据备份 SQLite 与 Hosts 在 PVC /data 定期备份 PVC 或库文件

六、使用与运维要点

日常使用

  • 导入 Rancher Cluster / Project kubeconfig
  • 点「测试」完成连通、权限与入口探测
  • 域名解析不到时用页面 Hosts（约 2 秒生效）
  • 「选用」后进入工作负载 / 监控 / 诊断

运维部署

  • 保留 PVC 升级，避免丢失库与 Hosts
  • 健康检查：/api/health
  • 可选自有 icon / banner 放入 etc 目录
  • 详情见仓库 docs/deploy.md、docs/api.md

安全建议

  • 生产环境通过 Ingress HTTPS 暴露
  • 限制 /igokey、/ops 仅内网可达
  • kubeconfig 按最小权限原则导入
  • 定期备份 /data（SQLite + Hosts）

不在范围内

  • 非多租户企业门户 / 计费平台
  • 非完整 kubectl / YAML 任意资源编辑器
  • 非替代 Rancher / 云厂商全量控制台
  • 目标集群侧能力仍受凭证限制
一句话总结：把「有权限的 kubeconfig」变成可浏览器操作的多集群运维台——接入快、依赖少、读写可控，适合日常巡检与轻量变更。
